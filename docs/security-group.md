# EC2 웹 접속과 보안 그룹 설정

**내 PC에서 EC2 웹페이지에 접속할 때는 인바운드 8080을 허용합니다.** 아웃바운드는 EC2가 외부 이미지 저장소·패키지 저장소 등에 먼저 요청할 때 사용합니다.

```text
내 PC ── 웹 요청 ──▶ [인바운드 8080] EC2 ──▶ nginx:80 ──▶ api:5000
EC2  ── 다운로드 ──▶ [아웃바운드 80·443] 외부 이미지·패키지 저장소
```

## 1. 실제 연결된 보안 그룹 열기

1. AWS 콘솔의 **EC2 → 인스턴스**에서 이번 실습 인스턴스를 선택합니다.
2. 아래 **보안(Security)** 탭을 선택합니다.
3. **보안 그룹(Security groups)**의 `sg-...` 링크를 누릅니다.

인스턴스에 연결된 그룹인지 확인합니다. 이름이 비슷한 다른 그룹을 수정하지 않습니다. 여러 보안 그룹이 연결되어 있다면 허용 규칙은 합쳐서 적용됩니다.

## 2. 인바운드: 내 PC의 웹 요청 허용

1. **인바운드 규칙 → 인바운드 규칙 편집 → 규칙 추가**를 선택합니다.
2. 아래 값을 입력하고 저장합니다.

| 입력 항목 | 값 |
|---|---|
| 유형 | 사용자 지정 TCP |
| 프로토콜 | TCP |
| 포트 범위 | **8080** |
| 소스 | **내 IP(My IP)** 또는 교수자가 지정한 강의실 공인 IP 범위 |
| 설명 | week8 web |

`내 IP`는 AWS 콘솔을 연 PC의 공인 IP를 기준으로 입력됩니다. `/32`는 해당 IPv4 주소 한 개를 의미합니다. 교실 PC의 내부 `192.168...`·`10...` 주소를 소스에 넣지 않습니다. 인터넷 연결이나 접속 장소가 바뀌면 현재 공인 IP를 다시 확인합니다.

**기존 SSH 22 규칙은 유지합니다.** 이 프로젝트의 인바운드 포트는 EC2 쪽 **8080**입니다. nginx 컨테이너의 80이나 Flask의 5000을 추가로 공개하지 않습니다.

## 3. 아웃바운드: EC2의 다운로드 요청 허용

1. 같은 그룹의 **아웃바운드 규칙 → 아웃바운드 규칙 편집**을 선택합니다.
2. 현재 규칙을 먼저 확인합니다.
3. 이미 **모든 트래픽 → `0.0.0.0/0`**이 있으면 아래 통신도 허용되므로 그대로 둡니다.
4. 아웃바운드가 제한되어 있거나 규칙이 없다면 필요한 다음 규칙을 추가하고 저장합니다. 다른 기존 규칙은 임의로 삭제하지 않습니다.

| 유형 | 프로토콜 | 포트 범위 | 대상 | 목적 |
|---|---|---|---|---|
| HTTPS | TCP | **443** | `0.0.0.0/0` | GitHub·이미지 저장소·Python 패키지·AWS 서비스 요청 |
| HTTP | TCP | **80** | `0.0.0.0/0` | HTTP 방식 Ubuntu 패키지 저장소 요청 |

`0.0.0.0/0`은 여기서 **모든 IPv4 목적지**를 뜻하며, 지정한 프로토콜·포트의 나가는 요청을 허용합니다. 외부에서 EC2의 모든 포트로 들어오는 것을 허용하는 설정이 아닙니다.

**아웃바운드에 8080을 추가하는 것으로 내 PC의 웹 접속이 열리지는 않습니다.** 보안 그룹은 상태를 추적하므로, 허용된 인바운드 웹 요청에 대한 응답은 아웃바운드 규칙과 무관하게 나갈 수 있습니다.

아웃바운드 허용은 네트워크 통신 조건입니다. 학교의 인증서 오류·프록시 차단이나 AWS 작업 권한 부족을 이 규칙으로 해결할 수는 없습니다.

## 4. 내부 확인 후 외부 접속

EC2 Ubuntu 터미널에서 확인합니다.

```bash
cd ~/week8_practice
sudo docker compose ps
curl -i http://localhost:8080/api/health
```

api가 healthy, nginx가 실행 상태이고 응답이 **200·`status: ok`**인지 확인합니다. 그런 다음 EC2 콘솔에서 **현재 퍼블릭 IPv4 주소**를 복사해 PC 브라우저에서 엽니다.

```text
http://EC2퍼블릭IP:8080
```

| 결과 | 다음에 확인할 것 |
|---|---|
| EC2 내부에서도 실패 | `sudo docker compose logs --tail=50 api nginx` |
| 내부는 성공, PC에서는 실패 | 현재 퍼블릭 IP → 실제 연결된 보안 그룹 → 인바운드 8080·현재 소스 IP |
| 보안 그룹도 맞는데 외부 접속 실패 | 서브넷의 `0.0.0.0/0 → 인터넷 게이트웨이` 경로, 학교망의 목적지 포트 허용 여부 |
| 이미지·패키지 다운로드 실패 | 아웃바운드 80·443 → 인터넷 경로 → 오류 메시지의 인증서·프록시·권한 원인 |

## ECS Fargate로 넘어갈 때

이번 Compose 실습은 **EC2:8080**, 이후 Fargate 실습은 **현재 태스크 IP:80**으로 접근합니다. Fargate Service 생성 시 선택한 **태스크용 보안 그룹**의 인바운드 80을 본인/강의실 공인 IP 범위에 허용합니다. 아웃바운드 HTTPS 443은 ECR 이미지 받기·CloudWatch 로그 전송에 사용됩니다. 퍼블릭 IP 할당과 인터넷 게이트웨이로 향하는 경로도 확인합니다.
